Parallel MCTS & Capstone Research Guide

The 4 Phases of Monte Carlo Tree Search

  1. Selection: Starting at the root, traverse down the tree using the Upper Confidence Bound applied to Trees (UCT) until a leaf node or an unexpanded node is reached. UCT balances exploiting high-win branches and exploring less-visited moves.
  2. Expansion: If the selected leaf is not terminal and has legal moves not yet in the tree, create one or more child nodes.
  3. Simulation (Rollout): From the newly expanded node, simulate the remainder of the game to completion using rapid, random moves (or domain heuristics).
  4. Backpropagation: Propagate the outcome of the rollout (+1 for win, 0.5 for draw, 0 for loss) backwards up the entire ancestral path, incrementing visit counts $N$ and accumulating total reward $Q$.

Shared Tree Parallelization Strategies

1. Tree-Parallel (Standard UCT with Mutexes)

Multiple workers traverse one shared tree. Coarse locks protect tree expansion and node statistics. Under many threads, workers queue on locks (lock contention), and workers often select identical paths concurrently before rollouts finish.

2. Virtual Loss (VL-UCT)

When a worker selects a path, it temporarily applies a Virtual Loss penalty ($L$) and increments virtual visits ($V$). This artifically reduces the UCT score of that branch for other workers, nudging concurrent workers to explore alternative branches without blocking! When the rollout completes, the virtual loss is removed and real reward is backpropagated.

3. WU-UCT (Weighted-Update UCT / Asynchronous Pipeline)

Decouples Expansion Workers (fast lock-free tree traversal) from Simulation Workers (slow rollouts) via a work queue. Uses a two-phase protocol: Update-Incomplete marks pending simulations ($O$ unobserved count) to discourage duplicate expansion; Update-Complete commits true simulation results.

4. Root Parallelization

Each worker runs its own completely independent MCTS tree. At decision time, visit counts for root actions are aggregated across all trees. Zero locks, zero synchronization overhead, perfectly embarrassingly parallel.

Mathematical Formulations Compared

Standard UCT

UCT = (Q / N) + c * sqrt( ln(N_parent) / N_child )

Virtual Loss (VL-UCT)

UCT = (Q - L) / (N + V) + c * sqrt( ln(N_parent) / (N_child + V) ) Where $L$ is total virtual loss and $V$ is number of threads actively exploring the node.

WU-UCT

UCT = (Q / N) + c * sqrt( ln(N_parent + O_parent) / (N_child + O_child) ) Where $O$ is the count of unobserved (in-flight) simulations in the work queue.

Capstone Findings & The Orienteering Problem

The Orienteering Problem (OP): An NP-hard combinatorial problem combining the Knapsack Problem and TSP. Given a graph with prize rewards at each vertex and a travel budget $T_{\max}$, find a path starting at node 1 and ending at node 2 that maximizes total collected prize within $T_{\max}$.

Crucial Takeaways from this Repository:

  • Root Parallelization was the Empirical Winner in Python (2.8x - 10.6x faster than WU-UCT): Because Python's Global Interpreter Lock (GIL) and lock convoys at the root node during backpropagation penalize shared-tree locking heavily.
  • Fine-Grained Locking Failed: An attempt to optimize WU-UCT by adding fine-grained per-node locks degraded multi-worker performance because backpropagating threads created lock convoys through root ancestors.
  • Why VL-UCT and WU-UCT Matter: In languages without a GIL (C++, Go, Rust) or when rollouts involve heavy deep learning evaluations (AlphaGo/AlphaZero), shared-tree search sharing is essential to prevent redundant compute.
